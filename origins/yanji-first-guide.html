📦 技术栈

React 18 Vite 6 Zustand marked + highlight.js GitHub Pages
  • React + Vite：构建快，HMR 流畅，适合单人维护
  • Zustand：比 Redux 轻得多，状态直接持久化到 localStorage
  • marked：把 AI 返回的 Markdown 渲染成 HTML，支持代码高亮
  • 部署在 GitHub Pages，不需要自己的服务器

🚀 部署流程

1 初始化项目结构 
your-repo/
├── yanji-src/        ← Vite 源码
│   ├── index.html
│   ├── vite.config.js
│   ├── package.json
│   └── src/
└── .github/
    └── workflows/
        └── yanji-build.yml
2 配置 vite.config.js 
export default {
  base: '/your-repo-name/yanji/',
  build: {
    outDir: '../yanji',
    emptyOutDir: true,
  },
}
3 配置 GitHub Actions

在 .github/workflows/yanji-build.yml 里写自动构建脚本，push 到 yanji-src/** 时触发 npm install → vite build → git commit → git push。

4 在 GitHub 仓库 Settings → Pages 开启

Source 选 Deploy from a branch，Branch 选 main，根目录选 /（不是 /docs）。

⚠️ 避坑指南

坑一：index.html 里的 script 路径

❌ 错误写法
<script type="module" src="/your-repo/yanji/src/main.jsx"></script>
✅ 正确写法
<script type="module" src="/src/main.jsx"></script>

Vite 开发服务器以 yanji-src/ 为根目录运行，index.html 里只需要写相对于这个根的路径。绝对路径加上 repo 名会找不到文件。

坑二：GitHub PAT 需要 workflow 权限

❌ 症状

push 时报错 refusing to allow a Personal Access Token to create or update workflow

✅ 解决

生成 PAT 时勾选 workflow scope（默认不勾，但推送 .github/workflows/ 里的文件必须有这个权限）。

更新 remote URL：

git remote set-url origin https://NEW_TOKEN@github.com/你的用户名/仓库名.git

坑三：push 大文件超时 / RPC failed curl 55

❌ 症状

push 时卡住，或者报 RPC failed; curl 55 Send failure

✅ 解决
git config http.postBuffer 524288000
git config http.version HTTP/1.1

前者把缓冲区加到 500MB，后者避免 HTTP/2 多路复用带来的连接问题。

坑四：emptyOutDir: true 会清空输出目录

⚠️ 注意

如果 outDir 指向 ../yanji，开了 emptyOutDir: true 后每次构建会先删掉 yanji/ 里的所有文件再重新生成。

✅ 好处 & 风险

好处：不会留下旧的过时文件。风险：如果 yanji/ 下还有手动放的其他文件，会一起被删。确认只用来放构建产物就可以放心开启。

坑五：node_modules 被 git 追踪

❌ 症状

第一次 commit 时把 yanji-src/node_modules/ 全推上去了，push 超慢或直接超时

✅ 解决

先在 .gitignore 里加上 node_modules/，然后从 git index 里移除（不删本地文件）：

git rm -r --cached yanji-src/node_modules/
git commit -m "remove node_modules from tracking"

🔐 记忆库 API 权限设计

如果你的言叽接入了外部记忆库（比如 moon-memory），给 AI 工具调用开权限时要注意：

  • ✅ 允许：搜索记忆、写入新记忆
  • ❌ 禁止：删除记忆

只暴露 search_memories 和 write_memory 两个工具定义，不在 AI 可调用的工具列表里加删除接口。这样即使 AI 判断失误，也不会把重要记忆删掉。

// 只暴露这两个给 AI
const AI_TOOLS = [
  { name: 'search_memories', ... },
  { name: 'write_memory', ... },
  // ← 没有 delete_memory，永远不加
]
